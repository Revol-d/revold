# Onde pedir ajuda

Este é o mapa de para onde levar cada tipo de dúvida sobre o **revold**. A ideia é simples: o
conhecimento do projeto já está escrito em algum lugar. Procure ali primeiro, e abra uma issue
quando não achar.

## Antes de perguntar, procure

1. **[Base de conhecimento (docs/kb/)](docs/kb/README.md)**: gotchas, decisões e caminhos que já
   custaram para alguém. É o primeiro lugar a olhar antes de reexplorar o código.
2. **[docs/](docs/)**: arquitetura ([ARQUITETURA.md](docs/ARQUITETURA.md)), fluxo de branch
   ([branch-strategy.md](docs/branch-strategy.md)), versionamento e deploy
   ([versionamento-e-deploy.md](docs/versionamento-e-deploy.md)) e a
   [aula de arquitetura](docs/onboarding/arquitetura-monorepo.md).
3. **[README.md](README.md)**: visão geral, comandos e a lista de unidades.
4. **[CONTRIBUTING.md](CONTRIBUTING.md)**: setup, fluxo de trabalho e padrões de código. A seção 12
   lista os erros comuns e como sair de cada um.
5. O **`README.md` da unidade** em que você está mexendo: o que ela faz e o que ela não faz.

## Onde levar cada coisa

| Situação | Onde |
|---|---|
| Dúvida de uso ou de desenvolvimento | Fale com um dos donos, ou abra uma issue com o modelo de **tarefa** |
| Encontrou um bug | Abra uma issue com o modelo de **bug** |
| Quer propor ou combinar uma mudança | Abra uma issue de **tarefa** e, quando alinhado, siga o [CONTRIBUTING.md](CONTRIBUTING.md) |
| Problema de segurança ou segredo vazado | **Não abra issue pública**. Siga a [SECURITY.md](SECURITY.md) |
| Dúvida sobre convivência ou conduta | [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) |

## Abrir uma issue

Use os modelos em [.github/ISSUE_TEMPLATE/](.github/ISSUE_TEMPLATE/). Eles pedem o mínimo para que
outra pessoa entenda o contexto sem precisar te perguntar de volta. Valem aqui as mesmas regras do
resto do projeto: sem emojis, e sem creditar IA como autora (divulgar **uso** de IA é bem-vindo).
